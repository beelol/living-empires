# Studio/replay bridge v1

This **trusted local operator adapter** records simulation outcomes and packages
them for Pulkit's Studio. It is not installed into the game loop yet. It grants
no release approvals, units, resources, ownership, or faction knowledge.
Keep its database and operator archives private. Do not host the CLI as an
unauthenticated endpoint. Files are created mode 0600.

## Producer contract

Python 3.9+, standard library only. From another Python adapter:

```python
from dev.studio.bridge import Journal
journal = Journal('/private/operator-state/world-history.sqlite')
event_id = journal.append({
    'key': 'world-action-123',       # stable authority idempotency key
    'source': 'simulation',
    'at': 1792950000,               # actual UNIX UTC seconds
    'tick': 120,                    # authoritative simulation tick
    'kind': 'action.completed',
    'payload': {'unit': 'worker-1', 'order': 'build-outpost'},
    'allowed_recipients': ['helios'], # exact faction IDs; [] = operator only
    'identity': {
        'world': 'world-1', 'seed': 42, 'release': 'EXACT_GAME_COMMIT',
        'rules': 'a' * 64, 'assets': 'b' * 64, # actual SHA256 fingerprints
    },
    'action': {'type': 'build', 'id': 'world-action-123'},
    'state': {'units': [], 'orders': []}, # real post-action authority snapshot
    'evidence': [],
})
```

The example is a fixture, not a real accepted build. The producer must record
requested, accepted, completed and rejected outcomes distinctly and supply only
facts the listed recipients can know in `payload`. Full `state` is operator-only;
**never include session tokens, API keys, credentials or raw saved-world files**.
Use a sanitized simulation snapshot. Private facts must be separate events with
separate recipient sets; the bridge cannot infer visibility from arbitrary JSON.
Use a different `source` namespace for each authority. No wildcard recipient.

The first event for rules replay is `kind: snapshot`, `action: null`, containing
the actual starting state. Append world changes after durable authoritative
commit, with the same stable action ID on retries. Production wiring needs the
authority's durable outbox (or transactional equivalent); two independent writes
cannot guarantee that every acknowledged game action reaches the bridge.
Bridge append acknowledges only after SQLite FULL-synchronous commit. A retry
after an uncertain response returns the same hash; changed data under the same
source/key fails. History is never reset automatically on parse/check failure.
Rust or other authority adapters can atomically publish one complete JSON event
file from their durable outbox and call this worker command outside the game tick:

```sh
python3 dev/studio/bridge.py /private/operator-state/world-history.sqlite append --input /private/operator-state/accepted-event.json
```

It returns `{id: event_hash}` after commit. Retain the outbox entry until that
acknowledgment is durable; retries are safe. This is a local trusted file input,
not a player API or an automatic polling service.

Every record hashes canonical ASCII JSON (sorted keys, compact separators,
finite JSON values only), parent, accepted input, result, clocks and version
identity. SQLite's head detects accidental lost tails; store exported archive
hashes externally to detect replacement of an entire database. Hashing alone
does not authenticate a compromised trusted writer.

## Actual client images

Call `Journal.store_evidence(bytes, metadata)` before appending the event. Metadata
fields: `media_type` (image/png, image/jpeg or image/webp), `view`, `client` (exact
client revision), `assets` (SHA256), `at`, `tick`. Attach the returned digest in
the event's `evidence` list. Time/tick/assets must match the event. Each capture
event can carry multiple viewpoints. Use separate capture events when clocks
differ. Reviewed images must reference the exact candidate content hash in the
payload, alongside job/brief/version/check/budget/retry/entity references.
No screenshots are generated by this adapter. Render validity still needs the
independent game renderer/checker. Missing images remain missing evidence.

## Studio delivery

```sh
python3 dev/studio/bridge.py /private/operator-state/world-history.sqlite verify
python3 dev/studio/bridge.py /private/operator-state/world-history.sqlite export-studio --output /private/operator-state/delivery-001.zip
```

The new archive contains `manifest.json` and exact `evidence/<sha256>` bytes,
render provenance, events, timestamps, parent hashes, states and readable
top-level `diff: {set, remove}` against each predecessor. Nested values are
replaced together. Canonical records remain the integrity authority; diffs are
derived views. Export returns the archive SHA256 and refuses to overwrite an
existing delivery. No network upload or Pulkit endpoint is assumed. Importing
the archive must independently verify hashes before trusting bytes.

The receiver-side integrity checker is available without opening a database:

```sh
python3 dev/studio/verifier.py /private/operator-state/delivery-001.zip --sha256 EXACT_PRODUCER_ARCHIVE_SHA256
```

It checks the outer archive hash, every linked event and state fingerprint,
derived diff, referenced image bytes and capture time/content binding. Duplicate,
missing or unexpected archive members fail. It reads within explicit size limits
and never extracts files or activates assets. Pass the producer's archive hash
through a trusted channel; a hash supplied by an untrusted archive cannot prove
authenticity. This is transport integrity, not independent visual/gameplay review.

`reconstruct` prints the last recorded state. `Journal.reconstruct(hash)` retrieves
an earlier state. `Journal.replay(reducer, pinned_identity)` runs recorded actions
through the caller's exact pinned rules and verifies every resulting state hash.
It rejects missing starting snapshot, unavailable versions or divergence. It
does not execute model services or claim a seed alone reproduces model output.
The producer must retain generation/decision inputs and returned proposals as
separate operator records and pin nondeterministic outcomes in accepted actions.

## GM and empire notices

```sh
python3 dev/studio/bridge.py /private/operator-state/world-history.sqlite export-gm --recipient helios
```

Output is an array of the agreed GM v1 envelope:
`{id, source, at: integer UNIX UTC seconds, kind, payload, allowed_recipients}`.
The immutable event hash is the ID. No global sequence, full state, parent hash
or private evidence is exported. Unknown recipients receive `[]`. GM ingestion
deduplicates IDs and must preserve recipient restrictions. Repeat exports are
safe; consumers need durable dedup. This adapter does not trust model-chosen ACLs.

The GM owner has settled its host intake as `<world-state>.gm-inbox.json` and its
sidecar as `<world-state>.game-master.json`. Publish a deduplicated union of
explicitly named factions to that intake from the producer worker:

```sh
python3 dev/studio/bridge.py /private/operator-state/world-history.sqlite export-gm --recipient helios --recipient tide --output /private/operator-state/world.json.gm-inbox.json
```

This writes a complete JSON array by owner-only temporary file, file sync,
atomic replacement and directory sync. Existing ACLs remain unchanged; unknown
factions' private events and empty-ACL operator records stay excluded. The GM
owns durable import/dedup and routing; do not delete source history after export.
Publication is serialized with journal writes so older concurrent deliveries
cannot overwrite newer history. The command returns event count, SHA256,
`last_id` and `has_more`;
it does not start an automatic loop or call a model. Host worker wiring is still
owned by the GM stream and must be verified against actual events.

GM v1 limits are enforced: at most 1024 events and 1MiB per delivery,
16KiB serialized payload per event, 64 unique recipient IDs, and IDs/source/kind
of 1–160 ASCII letters/digits or `-_.:/`. When `has_more` is true, wait for the
GM's durable import receipt, then publish the next page with
`--after-event PREVIOUS_LAST_ID` and the **same** recipient set. Publishing alone
is not a receipt; do not advance based on the command's success or elapsed time.
Retry the same page after uncertainty. The GM deduplicates event IDs. Unknown
cursors and incompatible source records fail explicitly; no silent omission.
Single-recipient stdout exports fail if paging is needed; use the file publisher.

The current GM demo ledger also has a **lifetime cap of 1024 unique events**.
Pagination does not remove that cap. Its durable receipt is the imported IDs in
`<world-state>.game-master.json` under `events[].id` (upcoming operator status:
`game_master.events[].id`). When full, the consumer must report blocked and keep
history; do not rotate/delete IDs or advance past unacknowledged events. Sustained
world operation needs the GM owner's durable indexing/retention upgrade before
this can be called a continuously integrated production loop.

Only the existing release authority may append `kind: content.activated` after
the exact approved file fingerprint really activates. Required payload fields:
`content_hash` (SHA256), `activation_id` (stable unique release ID). Also include
job, brief, role, gameplay capabilities, compatible format, costs, unlock rules,
checks/reviewer references and affected entity IDs when supplied by that authority.
Use the ACL for eligible factions. Reusing activation ID with changed fingerprint,
identity or eligibility fails. Rollback is a new activation ID referring to the
restored version. Proposal/job completion events never create pending notices.

`Journal.pending(faction)` returns unhandled activation envelopes across restarts.
The sole empire scheduler reads those and **current** knowledge, units, inventory,
manual orders and rights, then makes a feasible revised decision. It submits
normal validated paid build/recruit/move orders. After durable decision recording,
call `acknowledge(faction, ordered_notice_ids, decision_id, current_state_sha256)`.
All currently pending notices must be included or the ack fails as stale.
The state hash records the scheduler's input; the scheduler/authority must verify
that input is still current before effects. The bridge cannot inspect live state.
A late content notice invalidates the ack; retry the decision from fresh inputs.
Same decision+ack is idempotent; changed reuse fails. No ack means retry delivery.

## Ownership and current boundary

- Studio bridge owns this module and export contract.
- Argon GM chat owns its Rust inbox importer and recipient routing.
- Existing diplomacy/empire owner owns the sole live scheduler and action adapter.
- Game/release owners own durable outboxes, approval, exact-byte activation,
  roster unlock and paid/idempotent build effects.
- Pulkit owns Studio transport and generation/checker contract, not yet supplied.

The full authority -> Studio -> reviewed release -> paid useful unit in both
Bevy views loop remains **blocked** until those hooks and actual evidence exist.
Do not check off README ACs based on fixture unit tests.

Run: `python3 -m unittest discover -s dev/studio -v`.
