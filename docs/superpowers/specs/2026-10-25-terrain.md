# Terrain design

User direction: build excellent terrain alongside the model-improvement loop. The full README remains canonical; “perfect” means evidence against its observable requirements, not an assertion of flawless software. User authorized execution on 2026-10-25.

## Approach

Build baked, seeded terrain records and a shared query layer, with a Bevy client rendering the same records. This supports stable geography and server-authoritative movement. A purely cosmetic terrain scene would not satisfy traversal or persistence; regenerating established geography from the current generator would violate EXP-10. Native Rust owns geography and validation; Lua retains bounded movement proposals.

First delivery: a 3072 by 3072 metre region with at least 4,000,000 square metres of connected walkable land, ocean edge, coast/grassland/wetland/jungle/luminous grove, coherent elevation/moisture/geology, stable serialized terrain and deposits, ground-contact rendering, bounded mesh creation, authoritative terrain traversal rejection, compatible recovery of existing commander saves, and actual render evidence. Full economy, fog of war, frontier expansion, building collision, events, and production content approval remain dependencies, not invented passes.

## Contracts (terrain v1)

Coordinates are metres, x/y in simulation map to x/z in Bevy, Y up. Grid spacing 8 metres; 384 cells per axis, 385 vertices. Chunks have 16 cells (128 metres); 24 chunks per axis. Origin (0,0), ocean height 0. Height query must match triangle interpolation used by renderer, never a separate noise function. Generator version is retained with baked data; load must not regenerate saved geography. Samples and all dimensions must validate before allocation or use. Content fingerprints bind exact geometry.

`argon_dev::terrain` is the intended export (host owner must hand off or supply it). The core owner supplies serializable `Terrain`, `TerrainChunk`, `TerrainInfo`, `Surface`, and `Biome`, generation, validated load/save, sample, bounded chunk extraction, and segment traversal checks. Exact public Rust signatures are settled in the core work record before consumers implement. Client geometry packets must exclude hidden deposit data. Deposits persist only in authoritative storage until visibility exists.

Rendering owner owns `game/src/terrain/` and `game/src/visual.rs`; integrates via `visual::install`. Parent owns `game/src/client.rs`, protocol, world integration, CLI, network tests and integration record. Render code gets validated terrain via a parent-provided resource, not a second independently generated world. Existing diplomacy owner retains server.rs and runtime lib.rs until explicit handoff. No dependency upgrades or broad rewrites.

## Evidence and limitations

Test three independently chosen seeds for area, connectivity, reachable biome samples, shared boundaries, bad coordinates, corrupted/truncated saves and stable reload. Test rejected moves, duplicate/retried commands and two real network clients. Record actual game screenshots with separate reviewing agent. Full EXP-09 needs actual mining and construction; UX-05 needs the specified two M2 devices and entity load. Those remain blocked until their dependencies exist. Do not check README boxes from unit tests.
