# Persistent playable terrain implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver shared, saved, attractive terrain with honest acceptance evidence.
**Architecture:** Baked server-owned terrain, one query implementation, bounded terrain packets and native meshes. Independent core/render workers use separate worktrees; parent integrates authority/networking after existing owner handoff.
**Tech Stack:** Existing Rust, Bevy, Lightyear, serde, SHA-256, stdlib Python. No new dependencies initially.
**Spec:** docs/superpowers/specs/2026-10-25-terrain.md and complete README.md.

## Global Constraints

- At least 4 square kilometres of connected traversable land; all five biomes, ocean edges.
- Audit three independently selected seeds, actual client views and independent review.
- Rust authority validates movement; saved geography is never regenerated on load.
- One worktree/claim per stream; serialized exports, schemas and main integration.
- Missing game or hardware dependencies remain blocked. Development activation is not LIVE approval.

## Review Focus

- Invalid/truncated terrain cannot silently reset the world.
- Renderer triangles and authoritative height agree at seams and diagonal edges.
- Streaming/reconnect cannot mix geography versions or expose private deposits.
- Old commander saves retain identities/positions or fail explicitly, never reset.
- Mesh generation is bounded per frame and resource handles are reclaimed on eviction.
